# Single-sequence explorer / 一配列エクスプローラー

## 起動と基本操作

`pip install '.[gui]'` → `sp-features gui` → http://127.0.0.1:8765 。
公開サーバー用の認証機能はありません。既定ではローカルホストのみで動きます。
配列または一配列のFASTAを入力し、解析します。「例を使う」は人工配列と
手動の切断注釈です。モデルの予測例ではありません。

切断位置は「この残基の直後」です。18なら18番目と19番目の間で、
18番目が−1、19番目が＋1です。位置0はありません。
全体の座標と出力範囲は1始まり・両端を含む形式です。
既存のPython領域APIの0始まり・半開区間とは区別してください。
SPのみモードでは入力末端がSPの終端と宣言され、成熟側は不明です。

配列ボタン・グラフ・切断点の拡大表示をクリックすると、選択残基が連動します。
マトリクスをクリックすると、対応する記述指標を絞り込みます。
マトリクスの数字は指標数であり、生理機能の強さではありません。
空欄の意味は「この実装に直接対応する配列指標がない」です。
露出度、無秩序、二次構造は配列尺度から作らず、別の注釈として取り込みます。

Advancedでは成熟側の集計範囲（既定10残基）を変更し、構造注釈や予測を読み込み、
解析済みの複数配列を比較できます。比較の各列は独立した解析結果です。
配列のアラインメントや生理効率の順位付けは行いません。

## 情報の種類

| 表示 | 意味 |
|---|---|
| 配列から計算 | 入力配列の残基係数・組成など |
| 入力情報 | 利用者が与えた注釈。実験確認済みとは限らない |
| モデル推定 | TSignal、または取り込んだ構造モデルの注釈 |
| 規則による推定 | 明示した規則で推定した領域境界 |
| 不明 | 未入力・未予測。ゼロで置き換えない |

SP終端が推定なら、その終端を使う成熟側の集計にも推定の出所が付きます。
領域集計は領域の出所とSP終端の出所を別々に保持します。
入力注釈がモデルと食い違う場合は入力を優先し、元予測と警告を保存します。
SPなしと切断点の同時指定は矛盾として拒否します。

## N/H/Cと物性の定義

N/H/C推定は、SP内部（先頭と末尾を除く）でKyte–Doolittle係数の和が
最大となる連続区間をHとする探索的規則です。残りの前後がNとCです。
正の区間がなければ推定しません。同点は最初の区間を採用します。
これは学習済み領域予測器でも、標準的な生物学的境界の保証でもありません。
TSignalはN/H/Cを出力しません。この規則は種類不明またはSec/SPIでのみ自動適用します。
Python APIの`boundaries=(n_end,h_end)`で外部境界を優先できます。

各範囲（全体、SP、N、H、C、切断直前6残基、成熟側N末端）で、
以下を計算します。集計の端は実際に入力された配列内に収めます。

| 指標 | 定義・出典 | 解釈上の限界 |
|---|---|---|
| 疎水性 | Kyte–Doolittle、KYTJ820101、残基係数の平均 | 膜通過確率ではない |
| 極性 | Grantham、GRAR740102、平均 | 溶媒への露出ではない |
| 体積 | Grantham、GRAR740103、平均 | 構造上の立体障害を直接計測しない |
| ヘリックス形成傾向 | Chou–Fasman、CHOP780201、平均 | 二次構造そのものではない |
| 柔軟性参照 | Vihinen、VINM940101、平均 | 9残基窓の原法の再現でも、剛直性の実測でもない |
| 電荷の簡易指標 | K+R−D−E、合計と平均 | pH・末端・Hisを含む正味電荷ではない |
| 組成 | 20残基別、PG/KR/DE/STNQの割合、Shannon entropy（bits） | 機能を直接予測しない |
| 疎水性モーメント | 100度/残基の仮想ヘリックス上のKDベクトル和/残基数 | 実際の構造は仮定しない |

−6〜−1、＋1〜＋6の残基種類も表示します。Sec/SPIと明示された場合に限り、
−3と−1がともにAGSC集合に属するかを記述します。切断効率の確率ではありません。
係数はAAindexの全20残基を取得し、`scales.json`に出典・取得日・元ファイルの
SHA256とともに保存しました。従来のKD・ヘリックス係数は既存の独立参照テストで検証済みです。

## TSignalの設定

公式ソース: https://github.com/Dumitrescu-Alexandru/TSignal
論文: https://doi.org/10.1093/bioinformatics/btad228

TSignal本体・公式チェックポイント・上流が指定する専用Python環境を準備します。
上流READMEはPython 3.7.7等の古い依存関係を指定しています。
本アプリのPython 3.12環境とは分けてください。
信頼する公式チェックポイントだけを使ってください（上流はtorch.loadを使用します）。

```bash
sp-features configure-tsignal \
  --root /absolute/path/to/TSignal \
  --python /absolute/path/to/tsignal-env/bin/python \
  --model /absolute/path/to/checkpoint.pth
```

設定は`~/.config/sp-features/tsignal.json`。`SP_FEATURES_CONFIG`で場所を変更できます。
GUIから任意の実行コマンドを設定する機能はありません。
次回解析から、未入力のSP有無・種類・切断位置を自動で補います。
上流の`main.py --test_seqs ... --test_mdl ... --tune_bert --train_only_decoder
--output_file ...`を実行し、実際のCSV列`seqs,pred_lbls,SP_type_prob,CS_prob`を読みます。
上流は先頭70残基を解析するので、その範囲を保存します。
ラベルが末端までSPで切断後ラベルがない場合、切断位置は不明です。
非連続SPラベル・混在SP種類・配列不一致・不正なスコアは拒否します。
スコアは上流の生softmax値で、校正済みの確率とは扱いません。
実行上限は600秒。エラー時は結果を偽造せず表示します。
GUIは解析ジョブを順番に実行し、実行中・待機中の解析を中止できます。
現在は永続キャッシュ・モデル自動ダウンロードを実装していません。

**検証範囲:** CSV読み込み、座標、注釈の優先順位、未設定時の処理、
API自動呼び出しはテスト済みです。本変更の開発環境には上流チェックポイントと
専用環境がなく、実チェックポイントによる推論は未検証です。

## 注釈の読み込み

構造JSONは全前駆体に合わせた1始まりの座標・残基・出所を含む配列です。
RSAとdisorderは0〜1、secondary_structureはH/E/C。
モデルの静的構造で示す露出度は、切断時の状態や効率を保証しません。

```json
[{"position":19,"residue":"D","rsa":0.3,"secondary_structure":"C",
  "basis":"model_prediction","source":"model name, version and structural state"}]
```

TSignal JSONは以下の形式です。配列のSHA256一致が必須です。
実行後の`prediction`フィールドもこの形式で再利用できます。

```json
{"source":"TSignal","sequence_sha256":"SHA256_OF_NORMALIZED_FULL_SEQUENCE",
 "has_sp":true,"type":"Sec/SPI","cleavage":18,
 "analyzed_range":[1,26],"type_score":0.8,"cleavage_score":0.6}
```

## 保存と再現

JSONは全解析結果と表示状態を保存し、再読込できます。
CSVは全指標を出所・範囲・定義付きで保存します。
HTMLは外部通信不要の静的レポート（現在選択中の物性図、全指標、注意、全JSON）です。
SVGは現在の物性グラフです。PDFはブラウザの印刷→PDF保存で出力します。
JSON/CSV/HTMLは画面のフィルタで指標を落とさず、全結果を保存します。

Frontend変更時は`cd frontend && npm ci && npm run build`。
生成物はPythonパッケージに同梱されるため、利用者にNode.jsは不要です。
既存CLIのSPのみFASTA処理と特徴量名は維持しています。
