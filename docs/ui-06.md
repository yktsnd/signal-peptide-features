# UI 0.6 — sequence and selection first

The results workspace places the sequence and cleavage position beside the selected residue inspector on desktop. On small screens the inspector follows the sequence, before property tracks. Known cleavage initializes a 24-residue viewport around the junction and selects +1 when present. A Go to +1 control restores that focus; unknown cleavage and SP-only inputs do not invent a mature residue.

## Information hierarchy

- Input: analysis action next to sequence; optional name in Advanced; compact TSignal state; live −1/+1 preview for supplied cleavage.
- Result: identification and annotation provenance in a compact header. Hashes and timestamps remain under Evidence; annotation conflicts have a visible disclosure.
- Sequence: full-input overview, local residues, preset intervals and expandable custom interval controls. Residues wrap on narrow screens. Overview and graphs support arrow keys alongside buttons and numeric interval entry.
- Inspector: coefficients next to selection, definitions and source links in a disclosure, imported structure provenance and an explicit unassessed state with an annotation-entry action.
- Tracks: aligned coordinate axes and selection lines; source/units remain visible, reading notes and display choices expand on request. Independent metric/track filtering is preserved.
- Metrics: compact desktop rows and labelled vertical records on phones; IDs remain in details and exports. Physiological/physicochemical matrix stays on desktop, with equivalent task-grouped links on phones.
- Methods: full definitions, peptides distinction, warnings and original JSON remain available. CSV, SVG, complete HTML report and analysis JSON preserve their contents.
- Usage: concise opt-in choice, full policy disclosure, stop/delete and feedback unchanged. The UI version is 0.6; registered control IDs are shared across native and hosted collectors. No scientific content is added to logs.

## Validation and limits

Static rendering covers all tabs, unknown/no-SP/SP-only/single/structure/10,000-residue states and restored views. Model tests cover coordinate/interval calculations, filtering and exports. CI browser checks cover desktop placement, keyboard graph selection, +1 focus, mobile ordering, matrix/list navigation, restored selection, existing exports, consent and deletion. Local visual browser QA is unavailable in the managed environment. Researcher observation and comprehension testing remain future work; no improvement in measured task success is claimed.

## Follow-up evaluation

Observe researchers locating cleavage and its basis, reading +1, selecting an interval, finding a scale source, exporting and restoring. Compare correctness, time, backtracking and task feedback with the previous UI. Use opt-in logs as supporting evidence; event counts do not establish comprehension or actual file saving. Define quantitative targets after collecting a baseline.
